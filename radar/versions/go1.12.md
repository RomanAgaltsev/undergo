# Go 1.12

Source: https://go.dev/doc/go1.12

## MADV_FREE became the default, and RSS stopped being the truth
→ candidate | gc
"On Linux, the runtime now uses `MADV_FREE` to release unused memory. This is
more efficient but may result in higher reported RSS. The kernel will reclaim the
unused data when it is needed. To revert to the Go 1.11 behavior
(`MADV_DONTNEED`), set the environment variable `GODEBUG=madvdontneed=1`."

This closes a three-release arc the radar has now found all of:

| release | behaviour |
|---|---|
| ≤ 1.11 | `MADV_DONTNEED` — RSS falls when memory is released |
| 1.12 – 1.15 | `MADV_FREE` — cheaper, RSS stays high until the kernel needs the pages |
| 1.16 + | back to `MADV_DONTNEED` by default, "so RSS will more accurately reflect the amount of physical memory being used" |

Four years of "my Go service reports more memory than it uses", introduced
deliberately and reverted deliberately. The gradeable question is which
*measurement* changes at each step — the Go heap figures never do.

## Finalizers started running sooner
→ candidate | weak
"The compiler's live variable analysis has improved. This may mean that
finalizers will be executed sooner in this release than in previous releases."

`weak/05-single-cycle-reclaim` counts forced collections until a finalizer runs
and measures one. This is where "one" became possible: a more precise liveness
analysis means a variable stops being live at its last use rather than at the end
of its scope, so the object becomes unreachable earlier and the finalizer is
queued a collection sooner.

It is also a warning. Code that assumed an object stayed alive because it was
still in scope became wrong here, which is exactly what `runtime.KeepAlive` is
for — and why `weak/05`'s probe uses it.

## Functions that only call another function became inlinable
→ candidate | compiler
"More functions are now eligible for inlining by default, including functions
that do nothing but call another function."

The trivial wrapper — the shape that appears everywhere in generated code and in
the standard library's fast paths — stopped costing a call. Two observable
consequences are stated in the same release: "developers must use
`runtime.CallersFrames` instead of iterating directly over `runtime.Callers`
results" because a single PC may now represent several frames, and "wrappers
generated by the compiler to implement method expressions are no longer reported
by `runtime.CallersFrames` and `runtime.Stack`".

A traceback stopped matching the source. `compiler/01-inlining-budget` grades what
fits the budget; this is what fitting costs you.

## fmt started printing maps in sorted order
→ candidate | types
"Maps are now printed in key-sorted order to ease testing", with the ordering
rules given in full: "nil compares low ... ints, floats, and strings order by `<`
... NaN compares less than non-NaN floats ... Pointers compare by machine address
... Interface values compare first by `reflect.Type` describing the concrete type
and then by concrete value."

Map *iteration* is deliberately randomised and always has been. Map *printing*
became deterministic here. Both facts are true at once, which is the question:
predict whether two programs that print the same map agree, and whether two that
range over it do.

The second half is better still: "non-reflexive key values like `NaN` were
previously displayed as `<nil>`. As of this release, the correct values are
printed." A `NaN` key can never be found by lookup, because `NaN != NaN` — so a
map can hold entries that are unreachable through their own keys, and the printer
had been unable to describe them.

## Trigonometry stopped being bit-for-bit reproducible
→ candidate | edges
"The functions `Sin`, `Cos`, `Tan`, and `Sincos` now apply Payne-Hanek range
reduction to huge arguments. This produces more accurate answers, but they will
not be bit-for-bit identical with the results in earlier releases."

More accurate and different. Pairs with 1.14's `math.FMA` and the open `GOAMD64`
pool row: three separate mechanisms by which the same floating-point expression
gives different bits on different builds of Go. A task can ask which of them are
*allowed* to differ under the specification — the answer for elementary functions
is that Go promises accuracy, not reproducibility.

## Frame pointers on arm64 cost about 3%
→ candidate | asm
"Go programs now also maintain stack frame pointers on `linux/arm64` for the
benefit of profiling tools like `perf`. The frame pointer maintenance has a small
run-time overhead that varies but averages around 3%."

A rare thing: a stated price for a debugging affordance. 1.17 extended frame
pointers to arm64 everywhere and 1.21 stopped auto-applying `NOFRAME` on amd64,
so this number is the cost of all of it. `asm/03-register-abi` and `asm/04`
both write `NOSPLIT` without paying for a frame; this says what a frame buys and
what it costs.

## Sweeping got faster when most of the heap survives
→ candidate | gc
"Go 1.12 significantly improves the performance of sweeping when a large fraction
of the heap remains live. This reduces allocation latency immediately following a
garbage collection."

The cost is paid by the *allocator*, not the collector — sweeping is lazy, so a
program that allocates right after a collection does the sweeping itself. That is
why the improvement shows up as allocation latency, and it is measurable by
timing allocations at known distances after a forced `runtime.GC()`.

## Nil pointer arithmetic became explicitly invalid
→ candidate | edges
"It is invalid to convert a nil `unsafe.Pointer` to `uintptr` and back with
arithmetic."

`edges/05-unsafe-pointer-rules` grades the six legal patterns. This is a
clarification that closes an obvious-looking loophole: pattern 3 permits
arithmetic folded into one expression, and starting from nil looks like it should
be allowed since no object is involved. It is not, because the result points into
no allocation at all — the same defect as the out-of-bounds case that task
measures `go vet` missing.

## reflect gained a map iterator
→ candidate | reflect
"A new `MapIter` type is an iterator for ranging over a map ... exposed through
the `Value` type's new `MapRange` method. This follows the same iteration
semantics as a range statement." Before it, reflective map iteration meant
`MapKeys`, which allocates a slice of every key. 1.18's `MapIter.Reset` then made
the iterator itself reusable — three releases to make reflective map iteration
allocation-free.

## Timers and deadlines started scaling
→ candidate | sched
"The Go runtime's timer and deadline code is faster and scales better with higher
numbers of CPUs. In particular, this improves the performance of manipulating
network connection deadlines." The first step of the timer rewrite that 1.14
continued and that became user-visible in 1.23 and 1.27. Every `SetDeadline` call
touches this, which is why it was worth several releases of work.

## Memory profiles stopped overcounting large allocations
→ candidate | alloc
"Go 1.12 improves the accuracy of memory profiles by fixing overcounting of large
heap allocations." A profiler that was wrong about exactly the allocations
`alloc/05-size-classes` cares about — the ones above the size-class ceiling. Worth
knowing when reading any pre-1.12 profile.

## go vet became an analysis framework
→ no action
"The `go vet` command has been rewritten to serve as the base for a range of
different source code analysis tools. `go tool vet` is no longer supported."
The foundation of `golang.org/x/tools/go/analysis` and every linter built on it,
including the ones this repository runs — but tooling architecture.

## GODEBUG can disable CPU extensions
→ no action
"Adding `cpu.`_extension_`=off` to the `GODEBUG` environment variable now disables
the use of optional CPU instruction set extensions in the standard library and
runtime." Genuinely useful for bisecting a hardware-dependent bug, and adjacent to
the `GOAMD64` question, but it selects an implementation rather than changing an
answer.

## -benchtime accepts an iteration count
→ no action
"`-benchtime=100x` runs the benchmark 100 times." Useful for the kind of exact
measurement this catalogue does, and worth knowing, but it is a test flag.
